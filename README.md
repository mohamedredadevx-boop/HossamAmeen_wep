# منصة مستر حسام أمين التعليمية

## نسخة Bootstrap

هذه نسخة تطوير منفصلة عن المشروع الأصلي، وتستخدم Bootstrap 5.3.8 كإطار CSS محلياً. ملف `assets/bootstrap.min.css` مضمن داخل المشروع ويُحمّل قبل `assets/style.css` حتى تحتفظ المنصة بتنسيقها المخصص؛ وتُطبّق أصناف Bootstrap على حقول النماذج. بعد استنساخ هذه النسخة شغّل `npm install` ثم `npm start` كالمعتاد.

## تحسين الظهور في محركات البحث

- اضبط `SITE_URL` على أصل الموقع العام عبر HTTPS، مثال `https://example.com`، ليبني الخادم `sitemap.xml` بروابط مطلقة صحيحة.
- يعرض `/robots.txt` قواعد الفهرسة ويستبعد لوحات الحسابات والرسائل وواجهات الإدارة.
- تأكد من ظهور الصفحات العامة في Search Console بعد النشر. هذا الإعداد لا يضمن ترتيباً أو فهرسة فورية.
- لا تُفهرس صفحات الدروس الديناميكية حالياً؛ تحتاج عناوين عامة ثابتة وبيانات وصفية مناسبة لكل درس قبل إضافتها إلى الخريطة.

منصة تعليمية عربية باتجاه RTL، مبنية بواجهات HTML وCSS وJavaScript وخادم Node.js. تشمل الحسابات، الكورسات وطلبات الالتحاق، الدروس، الشهادات، الإشعارات، الشات العام والرسائل الخاصة.

## المتطلبات والتشغيل

- Node.js إصدار 24 أو أحدث.
- افتح مجلد المشروع في الطرفية ثم شغّل `npm install` مرة واحدة.
- في Windows شغّل `run-local-server.bat` أو استخدم `npm start`. كلاهما يستخدم قاعدة المشروع الأساسية في `data/ameen.sqlite` وملفات `uploads/`.
- يفتح ملف التشغيل المحلي المنفذ `3001`. افتح `http://127.0.0.1:3001`. يستخدم المشغّل قاعدة `data/ameen.sqlite` والملفات في `uploads/`. مجلد `work/local-preview` غير موجود في النسخة الحالية.
- يستخدم حساب الإدارة التجريبي في نسخة المعاينة البريد `admin@ameen.local` وكلمة المرور `mkopmkop`. لا تستخدم هذه الكلمة خارج الاختبار المحلي.
- لا تفتح `index.html` مباشرة. وضع `file://` لا يشغّل الخادم أو تسجيل الدخول؛ كما تُمسح بيانات الحسابات التجريبية القديمة التي كانت تحفظ كلمات المرور كنص صريح.

يستمع الخادم افتراضياً على `127.0.0.1` حتى لا يصبح متاحاً على الشبكة دون إعداد صريح.

## حساب الإدارة

عند تشغيل `npm start` على قاعدة بيانات جديدة، ينشئ الخادم حساب إدارة التطوير الافتراضي:

- البريد: `admin@ameen.local`
- كلمة المرور: `ChangeMe123!`

أما `run-local-server.bat` فيستخدم إعدادات المعاينة المحلية داخل قاعدة المشروع الأساسية. الحساب محلي للاختبار فقط. قبل استخدام الخادم خارج الجهاز، انسخ `.env.example` إلى `.env` وغيّر القيم السرية، أو عيّن المتغيرات مباشرة:

```env
NODE_ENV=production
HOST=127.0.0.1
TRUST_PROXY=true
PORT=3000
SITE_URL=https://example.com
SESSION_SECRET=ضع_قيمة_عشوائية_فريدة_بطول_32_محرفا_على_الأقل
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=كلمة_مرور_فريدة_14_محرفا_على_الأقل_مع_أحرف_كبيرة_وصغيرة_ورقم_ورمز
```

ولإنشاء سر عشوائي محلياً استخدم `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`. القيم المثال في `.env.example` ليست أسراراً صالحة؛ وضع الإنتاج يرفضها إلى أن تستبدلها بقيم فريدة.

## النشر على Contabo Linux VPS

راجع [دليل النشر التفصيلي](DEPLOY-CONTABO-AR.md) لنقل قاعدة المعاينة إلى مجلدات الإنتاج الدائمة وضبط حساب الإدارة أول مرة.

Contabo VPS مناسب لأن المشروع يحتاج Node.js 24 وSQLite وكتابة ملفات محلية. خادم VPS غير مُدار: أنت مسؤول عن تحديث Linux وتأمين SSH والجدار الناري وNginx ونسخ البيانات احتياطياً.

1. أنشئ VPS بنظام Ubuntu LTS، وسجّل الدخول باستخدام SSH key. احتفظ بعنوان IPv4 العام، وحدّث النظام قبل تثبيت التطبيق.
2. ثبّت Node.js 24 LTS وNginx. تحقق من `node --version` و`npm --version`. قاعدة البيانات تستخدم `node:sqlite` المدمج، لذلك لا تحتاج إلى تثبيت خدمة SQLite منفصلة.
3. انشر ملفات التطبيق المطلوبة: `server.js` و`package.json` و`package-lock.json` و`db/` وملفات HTML و`assets/`. لا تنشر `node_modules/` أو أسرار جهازك أو قاعدة التطوير.
4. أنشئ مستخدم Linux مخصصاً للتطبيق ومجلدين دائمين خارج مجلد الإصدار، مثل `/var/lib/ameen-learning-platform/data` و`/var/lib/ameen-learning-platform/uploads`. امنح مستخدم التطبيق وحده صلاحية الكتابة عليهما.
5. ضع متغيرات الإنتاج في ملف إعداد محمي خارج مجلد التطبيق، واجعل صلاحياته للمالك فقط. استخدم `NODE_ENV=production` و`HOST=127.0.0.1` و`PORT=3000` و`TRUST_PROXY=true` و`SITE_URL=https://نطاقك`، إضافة إلى `SESSION_SECRET` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` و`AMEEN_DATA_DIR` و`AMEEN_UPLOAD_DIR`. لا ترفع هذا الملف إلى Git.
6. ثبّت الاعتماديات وشغّل فحوص المشروع: `npm ci --omit=dev` ثم `npm test`. شغّل التطبيق كخدمة systemd أو بواسطة مدير عمليات موثوق كي يعاود التشغيل بعد إعادة تشغيل VPS.
7. اضبط Nginx كوكيل عكسي للدومين إلى `http://127.0.0.1:3000`، وفعّل HTTPS. اجعل Nginx يمرر `Host` و`X-Forwarded-Proto` ويضيف عنوان العميل في نهاية `X-Forwarded-For`. لا تفتح منفذ التطبيق 3000 للعامة؛ افتح SSH وHTTP وHTTPS فقط، وقيّد SSH بعنوانك إن أمكن.
8. اضبط نسخاً احتياطية مشفرة خارج VPS تشمل قاعدة SQLite ومجلد المرفقات، واختبر الاستعادة. لا تعتمد على Snapshot الخادم كنسخة وحيدة لبيانات الطلاب.

يرفض التطبيق بدء وضع الإنتاج إذا كانت أسرار الإنتاج أو `SITE_URL` أو مسارات التخزين الدائمة مفقودة، أو إذا كانت مسارات البيانات داخل مجلد الإصدار. اختر منطقة الخادم الأقرب لطلابك عند الشراء، وتحقق من تفاصيل السعر والموارد وشروط النسخ الاحتياطي في لوحة Contabo وقت الطلب.

فعّل `TRUST_PROXY=true` فقط مع وكيل Nginx محلي موثوق، ولا تسمح بالوصول المباشر إلى منفذ التطبيق. إذا لم تستخدم وكيلاً عكسياً موثوقاً، اتركه `false` واستخدم عنوان الاتصال الذي يراه Node.js لحدود المحاولات.

عند نقل قاعدة المعاينة الحالية إلى الإنتاج، عيّن `ADMIN_EMAIL` إلى بريد المدير الفعلي. في أول تشغيل فقط اجعل `ADMIN_RESET_PASSWORD` و`ADMIN_PASSWORD` متطابقين مع كلمة مرور فريدة من 14 محرفًا على الأقل تضم أحرفًا كبيرة وصغيرة ورقمًا ورمزًا، واضبط `RESET_ADMIN_PASSWORD=true`. بعد نجاح التشغيل احذف `RESET_ADMIN_PASSWORD` و`ADMIN_RESET_PASSWORD`، وأبقِ `ADMIN_PASSWORD` مضبوطًا على القيمة نفسها. إعادة التعيين تُبطل الجلسات الحالية.
## البيانات والملفات

- تحفظ بيانات المنصة افتراضياً في قاعدة SQLite `data/ameen.sqlite`. ينشئ الخادم الجداول من `db/schema.sql` تلقائياً عند التشغيل. استخدم `AMEEN_DATA_DIR` لتوجيه مجلد البيانات والقاعدة إلى مساحة دائمة، ويمكن استخدام `AMEEN_DATABASE_PATH` لتحديد ملف القاعدة بشكل مستقل.
- عند أول تشغيل بعد هذا التحديث، يستورد الخادم البيانات الموجودة في `data/store.json` إلى SQLite إذا كانت القاعدة فارغة. يظل ملف JSON الأصلي كما هو كنسخة احتياطية؛ بعد التأكد من النقل، قاعدة SQLite تصبح مصدر البيانات المعتمد.
- يتطلب تشغيل التطبيق Node.js 24 أو أحدث لتوفير `node:sqlite` المدمج. لا توجد حاجة لإضافة حزمة قاعدة بيانات خارجية.
- تُحفظ المرفقات افتراضياً في `uploads/`، ويمكن تغيير المسار باستخدام `AMEEN_UPLOAD_DIR`. يجب حفظها خارج مجلد الإصدار الحالي ومستودع Git؛ الخادم لا يخدمها إلا بعد التحقق من الجلسة وصلاحية المستخدم.
- قاعدة SQLite مناسبة لخادم واحد. لا تشغّل عدة نسخ من التطبيق على ملف قاعدة البيانات نفسه، وخذ نسخة احتياطية متناسقة من القاعدة ومجلد المرفقات واختبر الاستعادة.
- خذ نسخة احتياطية مشفرة ومنتظمة من `data/` و`uploads/`، واختبر استعادتها.

## الحماية المطبقة

- الملفات العامة محددة بصفحات HTML وملفات JavaScript وCSS داخل `assets/`؛ ملفات الخادم والإعدادات والبيانات غير متاحة عبر مسارات الويب.
- تنزيل صور وتسجيلات الشات وملفات الدروس يتطلب جلسة، وملفات الدروس تتطلب صلاحية المقرر أو التسجيل فيه.
- جلسة الدخول في Cookie من نوع `HttpOnly`، وتنتهي بعد سبعة أيام. تغيير كلمة المرور أو تعطيل الحساب أو تغيير دوره أو تسجيل الخروج يبطل الجلسات السابقة.
- محاولات الدخول وطلبات الاستعادة والتسجيل والرفع والرسائل محدودة المعدل في SQLite، بمفاتيح مجزأة، وتبقى الحدود بعد إعادة تشغيل التطبيق. شغّل نسخة واحدة فقط على ملف القاعدة.
- يفرض الخادم حداً أقصى لرفع ملف واحد في كل مرة، وحدود حجم منفصلة حسب النوع، ويتحقق من ترويسة الملف الفعلية قبل حفظه. هذا التحقق يمنع انتحال نوع الملف، لكنه لا يفحص البرمجيات الخبيثة؛ أضف خدمة فحص ملفات إذا كانت متاحة في بيئة الاستضافة.
- في وضع الإنتاج لا تُحفظ الملفات المرفوعة إلا بعد اجتياز ClamAV؛ إذا كان `clamscan` غير مثبت أو تعذر الفحص أو انتهت مهلته، يرفض الخادم الرفع ولا يترك الملف في مجلد المرفقات. ثبّت ClamAV وحدّث قواعده، واضبط `CLAMSCAN_PATH` إذا اختلف مساره. التشغيل المحلي لا يفرض الفحص افتراضياً.
- لا تُكتب معاملات الرابط في سجل الطلبات، لتجنب تسجيل تذاكر تنزيل الوسائط.
- رموز الكورسات أطول وعشوائية، وطلبات الكورس محدودة المعدل.
- لا تُسجّل مشاهدة الدرس مكتمَلة إلا بعد إنشاء جلسة مشاهدة وانتظار 60 ثانية على الأقل وإرسال تقدم لا يقل عن 60 ثانية. تحقق المتصفح لا يثبت وحده أن الطالب شاهد الفيديو فعلياً؛ الشهادات الرسمية تحتاج اختبارات أو خدمة بث وتحقق موثوقة.

## الكورسات المدفوعة وFawryPay

- يحدد المدرس أو المدير الفئة، المرحلة، السعر بالجنيه المصري، المجانية، وحالة النشر عند إنشاء الكورس أو تعديله. لا يظهر الكورس المنشور إلا لمرحلة الطالب.
- يرسل الطالب طلب الالتحاق أولاً. الكورس المجاني يُفعّل بعد موافقة المدرس المسؤول أو المدير. الكورس المدفوع يحتاج الموافقة وتأكيد الدفع قبل فتح المحتوى.
- لتعطيل الدفع اترك `FAWRY_MERCHANT_CODE` و`FAWRY_SECURE_KEY` بلا إعداد. للدفع الفعلي اضبطهما من لوحة الاستضافة، واضبط `FAWRY_WEBHOOK_URL` على عنوان HTTPS عام يطابق `/api/payments/fawry/webhook`، ثم سجل العنوان مع فريق FawryPay. لا تحفظ مفتاح الأمان في ملفات الواجهة أو المستودع.
- يستخدم الخادم بيئة FawryPay التجريبية افتراضيًا أثناء التطوير، وإنتاج FawryPay في وضع الإنتاج. يمكن تحديد `FAWRY_API_URL` صراحةً إذا زودك FawryPay بنقطة تكامل مختلفة.
- في الإنتاج يجب ضبط متغيرات فوري الثلاثة معاً أو تركها كلها فارغة. عند إعدادها يتحقق الخادم أن عنوان الإشعار HTTPS وعلى نفس أصل `SITE_URL`، وأن نقطة الدفع ضمن نقاط فوري المعتمدة؛ إعداد ناقص أو غير متطابق يمنع إقلاع الإنتاج بدلاً من ترك الدفع في حالة غير واضحة.
- يتحقق الخادم من توقيع SHA-256 لاستجابة إنشاء الدفع وإشعار الخادم، ومن رقم الطلب والمبلغ قبل تحديث حالة الطلب. لا توجد وسيلة تأكيد دفع تجريبية في الإنتاج.
- الدفع الفعلي لن يعمل قبل توفير بيانات تاجر فوري وتفعيل طُرق الدفع المطلوبة وتسجيل إشعار HTTPS لدى فوري. لا يكفي إعداد التطبيق وحده لتفعيل حساب التاجر.

توثيق التوقيع وطلب الدفع وإشعار الخادم: [إنشاء طلب دفع FawryPay](https://developer.fawrystaging.com/docs/server-apis/create-payment-refno-apis) و[إشعار الخادم V2](https://developer.fawrystaging.com/docs/card-tokens/payment-notifications/server-notification-v2).

## المحادثات والملفات

- الشات العام مقسّم إلى مجموعات الصفوف الثانوية الثلاثة، ويمكن للمدرس والمدير التنقل بينها. تظل رسائل المجموعات القديمة محفوظة في قاعدة البيانات.
- يمكن إرسال نص وصورة وفيديو MP4/WebM وتسجيل صوتي في المجموعتين والرسائل الخاصة. يحذف المدرس أو المدير الرسائل، ويستطيع المدير مسح مجموعة أو سجل الشات بالكامل.
- الصور الشخصية والملفات الخاصة محمية بتسجيل الدخول، وملفات المحادثة الخاصة لا يعرضها الخادم إلا لطرفي المحادثة.
- رابط فيديو الدرس يقبل MP4/WebM أو YouTube/Vimeo. تحويل روابط YouTube إلى تضمين خصوصي ويقتصر الرابط المقبول على نطاقات الخدمة المعروفة.

## إدارة المحتوى والامتحانات

- يستطيع المدرس إدارة الكورسات التي أنشأها، ويستطيع الأدمن إدارة جميع الكورسات: تعديل البيانات أو الحذف.
- من صفحة تفاصيل الكورس يمكن إضافة محاضرات فيديو MP4/WebM أو YouTube/Vimeo. ملف PDF اختياري ويمكن إضافته أو استبداله، كما يمكن حذف المحاضرة.
- يمكن إنشاء امتحانات اختيار من متعدد وإضافة صورة لكل سؤال؛ تُحفظ الإجابة الصحيحة على الخادم وتُحسب نتيجة الطالب بعد الإرسال.
- تظهر الامتحانات للطلاب المسجلين في الكورس فقط. شاشة الإدارة تعرض مفتاح الإجابة للمدرس المالك وللأدمن.
- نموذج التواصل يحفظ الرسائل ويعرضها للأدمن حتى عند عدم إعداد SMTP. يُستخدم SMTP لإرسال نسخ البريد.

## إعداد البريد

يمكن تفعيل البريد عبر `SMTP_HOST` و`SMTP_PORT` و`SMTP_USER` و`SMTP_PASS` و`SMTP_FROM`. تبقى الإشعارات داخل المنصة متاحة حتى دون SMTP.

## إعدادات ومكونات المشروع

- الخادم ومسارات API: `server.js`
- الواجهات والتفاعلات: `assets/app.js`
- التصميم: `assets/style.css`
- بيانات التشغيل والملفات المرفوعة: `data/` و`uploads/`
- النسخ الاحتياطية وتمرين الاستعادة: `scripts/backup-data.js` و`scripts/verify-backup.js`؛ يجب أن تكون وجهة النسخ خارج مجلد التطبيق.
